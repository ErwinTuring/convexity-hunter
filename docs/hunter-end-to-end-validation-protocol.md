# Hunter End-to-End Validation Protocol v0.1

## Status and purpose

```text
protocol_status = FROZEN
initial_campaign_target = 5
```

This lightweight documentation protocol diagnoses where consecutive fresh
Hunter product samples lose research value. It introduces no production
schema, API, orchestration layer, ranking, score, recommendation, or automatic
promotion.

The tested path is:

```text
public world
    -> bounded Hunter candidates
    -> explicit human discovery interest
    -> accepted Event Intelligence hypothesis
    -> legitimate real option comparison surface
    -> Probability-Free Convexity Discrimination
    -> explicit human research preference or NONE
```

Each sample records exactly one primary terminal outcome. Operational failures
remain distinct from product-negative evidence.

## Exact terminal taxonomy

### `NO_CANDIDATES`

The bounded producer emitted a valid zero-candidate batch. This is discovery-
layer evidence, not producer failure.

### `HUMAN_NONE_AT_DISCOVERY`

One or more valid candidates were presented, but the human selected `NONE`
because none warranted further research. This is Hunter/discovery-value
evidence and is not an execution failure.

### `EI_NOT_ACCEPTED`

The human selected one candidate, but provenance-preserving translation,
supplemental verification, and the existing Event Intelligence boundary did
not produce a currently accepted hypothesis. The exact `INCOMPLETE`, rejected,
or stale reason is retained; missing semantics are never repaired merely to
continue.

### `NO_OPTION_RESEARCH_SURFACE`

Event Intelligence accepted the hypothesis, but existing maturity and Futu
Browser rules produced no legitimate option comparison surface. This is
separate from provider execution failure and authorizes no manufactured
structure.

### `OPTION_RESEARCH_NONE`

An accepted hypothesis reached a valid real option comparison surface,
Probability-Free Convexity Discrimination produced usable geometry, and the
human selected `NONE`. This is genuine downstream negative evidence.

### `OPTION_RESEARCH_PREFERENCE_FORMED`

An accepted hypothesis reached a valid real option comparison surface,
Probability-Free Convexity Discrimination produced usable geometry, and the
human explicitly selected one exact research structure. This means only
`worth continuing research`; it does not mean Engine acceptance, cheapness,
recommendation, positive expected value, tradeability, or execution readiness.

### `OPERATIONALLY_INCONCLUSIVE`

Infrastructure or experimental execution prevented the relevant product
question from being tested. The record must name the blocked stage and exact
failure, such as provider transport, malformed presentation, tooling failure,
or unavailable external discovery capability. It must not be converted into a
product-negative outcome.

## Initial campaign discipline

The pre-registered initial campaign contains five consecutive eligible fresh
samples. Only one sample is executed at a time, with every human checkpoint
preserved. The campaign must not stop early after a positive result, continue
until a preferred success rate appears, selectively discard `NONE`, or tune
Hunter policy and option metrics between samples to rescue weak output.

After five completed product samples, the campaign stops for synthesis before
any decision to expand toward ten. No arbitrary success-rate threshold is
defined in advance. Any later policy change is evaluated against, and does not
rewrite, the frozen prior samples.

## Per-sample protocol

1. Declare one unused inclusive seven-calendar-day source-publication window
   and exact retrieval `observed_at`.
2. Run bounded public Web Search under
   [`Hunter Discovery Policy v0.1`](hunter-discovery-policy-v0.1.md), preserving
   its three lanes, fact-versus-interpretation split, neutral policy order,
   at-most-ten limit, no padding, and no option-market feedback.
3. Present the complete validated `EventCandidateBatch` and stop for explicit
   human selection of one candidate or `NONE`.
4. Only after one selection, run source-backed supplemental verification and
   provenance-preserving translation through the existing Event Intelligence
   boundary. Do not infer dates, expected windows, reassessment, underlyings,
   or causal facts merely to reach acceptance.
5. Only after acceptance, apply the existing exact maturity authority.
   `HYPOTHESIS_ALIGNED` remains mandatory when a complete authoritative impact
   window exists; `NEUTRAL_STRUCTURAL_RESEARCH` is available only under its
   implemented eligibility rules and never converts reassessment into an
   impact end or maturity anchor.
6. If a legitimate Futu Browser surface exists, run the existing Probability-
   Free Convexity Discrimination contract. A real quote run uses one valid-RTH
   batch only, with no refresh, retry for better values, cherry-picking, or
   multi-batch stitching.
7. Persist and verify the complete sanitized comparison surface outside the
   repository before display. Present every row in neutral Browser order and
   stop for one explicit structure or `NONE`.
8. Assign exactly one terminal outcome and retain the stage-specific evidence.

Human-primary option presentation emphasizes expiration and strike,
premium/reference approximate percentage, conditional 1x/2x/5x/10x hurdle
percentages, and relative spread when available. The complete response ladder
and exact rational values remain auditable but do not dominate presentation.
This is presentation only and changes no calculation semantics.

## Required human observations

At discovery selection, retain:

- willingness to continue researching;
- whether the event itself was new;
- whether the event-to-underlying connection was new;
- impact/transmission credibility;
- principal rejection reasons; and
- selected discovery lane.

At option selection, retain:

- approximate structures confidently rejected;
- metrics that materially affected the decision;
- metrics mostly ignored or confusing;
- whether search effort was reduced;
- whether preference was possible without probability;
- whether authority disclosures constrained the decision appropriately; and
- whether the basis was deterministic geometry or an implicit expiry/strike
  heuristic.

## Hard boundaries

The campaign does not build or change Event Discovery, Event Intelligence,
maturity authority, Browser, discrimination, Candidate, screening, or report
contracts. It does not add a knowledge graph, narrative score, source-ranking
model, multi-agent orchestration, Skill, probability model, historical reach
frequency, automatic underlying/option selection, or recommendation system.
It does not resume the six frozen Engine `missing_*` work units.
