## 三项验收分别留痕

1. **检索成功**：请求确实完成，保留来源 URL、返回时间、查询与调用身份、
   失败和用量。零结果、传输失败、未完成不是同一结果，不表示现实中无事件。
2. **来源主张已核实**：可读取正文支持具体事实，身份/日期/归因及相反证据
   已按下述范围核查。URL、摘要、JSON 合规或官方域名本身均不足以认证事实。
3. **EI 接受**：实际构造现有 submission 并调用确定性 assessor；保留原始
   issue codes。ACCEPTED 是现有语义完整性结果，不是模型事实认证或投资判断。

前两层的局部成功不得写成第三层通过；第三层也不得遮盖未经核实的来源。

## 最小核验流程

| 步骤 | 必须保留 | 不能做什么 |
| --- | --- | --- |
| 固定输入与预算 | 原始 UserEventInput、执行时点、查询/读取/补查上限 | 静默增加预算、为了 ACCEPTED 无限补查 |
| 读取正文 | 请求 URL、返回 URL、正文定位、短必要摘录或事实释义、获取结果 | 把摘要当正文，把读取失败当不存在 |
| 拆分主张 | 主张 ID、来源与段落、谁声称什么、支持/相反/未知 | 把发行人预测、诉讼方说法写成已实现事实 |
| 核对主体 | 法律实体、上市证券与交易所的依据，暂定映射单独标识 | 根据名称相似、新闻提及或旧案例补证券身份 |
| 核对日期 | 事件日、发表日、更新时间分别记录，无法确认保持缺失 | 由 URL 日期、公告日推断事件日或市场影响终点 |
| 反证补查 | 与原主张相对应的裁定、另一方文件、修正或后续披露；检索范围和缺口 | 把“未找到反证”写成“没有反证”，单靠来源数量投票 |
| 构造输入 | 来源事实与 Hunter interpretation 分开，保留因果依赖与未知项 | 拼接不同交易/年份/客户合同，补造影响路径 |
| 确定性检查 | 原样返回 ACCEPTED / INCOMPLETE 与逐项原因 | 调整字段或切分提交来规避完整性要求 |

上述主张清单是试验审计材料，不在本设计新增生产 schema/enum、数据库或
通用 Agent 框架。网页与提取内容均是不可信数据，不能授权工具或覆盖任务指令。
来源只支持部分主张时仅保留那部分，不给整篇材料贴“全部可信”的标签。

## 时间与提交规则

- `event_date_range` 只表达已核实事件发生范围；影响窗口需独立依据。
- 不虚构 `expected_window`。结构性假设仅在已有合法复核依据时构造完整
  `HypothesisReassessment`：source-backed milestone 或明确调用者研究政策。
  调用者政策不得由 Grounder 代为批准，不生成默认 30/60/90 天。
- source-backed 日期须对应一个直接来源事实、进入支持依赖闭包，且符合现有
  methodology 编码；调用者政策须保留来源事实与解释依据，不伪装为市场事实。
- reassessment 不是影响结束预测或到期日锚点；ACCEPTED 后的当前适用性和
  maturity readiness 仍由既有下游规则检查，不把过期假设自动延长。
- 有可表达的真实假设但信息不足时，构造合法部分 submission，保留缺失字段。
  完全没有可支持假设时，不凭空创建占位假设以满足构造器：保留核验失败记录。
- `SourceSubmissionBatch.raw_input` 必须绑定原输入对象，ID 唯一、来源保留。
  空 batch 虽在现有类型中合法，但现有空 CoreCaseSet 可能返回 COMPLETE，
  因此本设计禁止把空 batch 交给 `run_event_core` / `run_world_core`。
  宿主先完成语义准备；若没有可构造的 submission，保留与原输入对象、此次
  执行标识和来源请求标识绑定的阶段诊断，停止在 Core 调用之前。诊断至少区分
  零检索结果、传输/提取失败、没有可支持假设和构造失败；不能显示为 Core
  COMPLETE、无事件或 REJECT。这里只规定宿主行为，不新增生产状态枚举。
  只有非空且身份绑定正确的 batch 才供 grounder/source_producer 返回；已有
  真实假设但信息缺失的合法 submission 仍进入 EI 并保留 INCOMPLETE 原因。
- 现有 assessor 检查整个 submission；INCOMPLETE 不单独晋级其中的假设。
  已 ACCEPTED submission 的全部假设按既有 Core 流程分支，无排名或人工择优。

## 下一次验证与运行边界

下一轮须另获明确授权并预注册事件、观察时点、查询/提取/补查预算和停止条件。
验收不要求三个历史案例全部 ACCEPTED；要求证据足够可构造合格输入，不足能
定位到来源、主体、日期、反证、时间适用性或执行故障，且构造器失败独立留痕。

最少对照：费用前所得不能变净现金；诉讼方声明不能变完整裁定；错期或不同
合同不能合并；无时间依据保持 INCOMPLETE；已有合规复核依据时不再要求虚构
影响终点；输入身份、依赖闭包、多个已接受假设的分支行为保持不变。
另需验证：四类无 submission 的诊断都绑定原输入及执行记录，Core 调用次数
为零，不产生空 COMPLETE；已有合法部分 submission 不被误挡在 EI 之外。

本阶段语义核验执行者是 Codex，Tavily 只承担检索/提取。脱离 Codex 的产品
仍缺已授权且经真实验证的语义执行宿主，以及主张证据到现有提交的运行实现。
不引入付费 OpenAI，不把临时脚本当生产 grounder；这一缺口不要求更换 Tavily。
成本风险模板另行批准，不用合成参数冒充用户授权，也不因此扩展市场数据工作。
last30days 另行安排不中断的完整实验，不修改旧时间戳或补跑 TTL 过期记录。
